# 은혜동산교회 홈페이지 — 배포 가이드

비용 0원 · 서버 없음 · Cloudflare Pages + KV 구조

## 1. 폴더 구조

```
church-site/
├── index.html              메인 화면 (성도용)
├── admin.html               관리자 화면
└── functions/
    └── api/
        ├── verify.js         POST /api/verify  (비밀번호 확인)
        └── config.js         GET/POST /api/config  (데이터 조회/저장)
```

이 구조 그대로 GitHub 저장소에 올리면 Cloudflare Pages가 `functions/api/*.js`
파일을 자동으로 서버리스 API로 인식합니다. 별도 백엔드 서버가 필요 없습니다.

## 2. 최초 1회 설정 (개발자가 진행)

1. **GitHub 저장소 생성** 후 이 폴더 전체를 업로드합니다.
2. **Cloudflare 대시보드 → Workers & Pages → Create → Pages → Connect to Git**
   으로 방금 만든 저장소를 연결합니다. 빌드 명령 없이(Framework preset: None)
   그대로 배포하면 됩니다.
3. **KV Namespace 생성**
   - Workers & Pages → KV → Create a namespace → 이름 예: `church-kv`
4. **Pages 프로젝트에 KV 바인딩 연결**
   - 방금 만든 Pages 프로젝트 → Settings → Functions → KV namespace bindings
   - Variable name: `CHURCH_KV` (반드시 이 이름이어야 코드가 인식합니다)
   - KV namespace: 3번에서 만든 `church-kv` 선택
5. **관리자 비밀번호 등록 (환경 변수)**
   - 같은 프로젝트 → Settings → Environment variables
   - Variable name: `ADMIN_PASSWORD`, Value: 교회에서 정한 4자리 숫자 (예: `1004`)
   - **Encrypt(암호화) 체크** 해서 저장 (Secret으로 등록)
6. 저장 후 **재배포(Retry deployment)** 한 번 실행하면 바인딩이 적용됩니다.

이후로는 개발자가 다시 손댈 일이 없습니다. 교회 관리자는 `admin.html`
화면에서 비밀번호만 입력하면 됩니다.

## 3. 관리자 사용법 (컴맹 대상 실제 매뉴얼)

1. `우리교회주소.pages.dev/admin.html` 접속 (즐겨찾기/바탕화면 아이콘으로 저장 추천)
2. 4자리 비밀번호 입력 → 확인
3. 유튜브 영상 링크를 붙여넣기 (유튜브 앱에서 공유 → 링크 복사)
4. 사진 선택 박스를 눌러 주보 사진 선택 (또는 카메라로 바로 촬영)
5. 맨 아래 **"홈페이지에 즉시 반영하기"** 버튼 누르기
6. "반영되었습니다" 문구가 뜨면 완료. "홈페이지 보기"로 바로 확인 가능

## 4. 이미지 업로드/저장 방식에 대한 설명 (요청하신 3번 항목)

### 채택한 방식: **브라우저에서 자동 압축 → Base64 → Cloudflare KV 저장**

가장 단순하고 사고 위험이 적은 방식을 선택했습니다. 이유와 동작 원리는 다음과 같습니다.

**왜 이 방식인가**
- 별도의 이미지 저장소(S3, R2 버킷 등)를 만들고 연결할 필요가 없어
  설정 단계가 최소화됩니다. (컴맹 관리자가 실수할 지점이 하나 줄어듦)
- 파일 업로드용 서명 URL 발급, CORS 설정 등 복잡한 과정이 전혀 없습니다.
- 완전 무료(Cloudflare KV 무료 티어: 하루 쓰기 1,000회, 값 하나당 최대 25MB)
  범위 안에서 주 1회 주보 교체 용도로는 충분합니다.

**동작 원리**
1. 관리자가 사진을 선택하면, 브라우저(`admin.html`의 JS)가 `<canvas>`를
   이용해 **가로 최대 1400px, JPEG 품질 82%**로 자동 축소·압축합니다.
   → 스마트폰 카메라 원본(수 MB~십수 MB)도 보통 200KB~1MB 수준으로 줄어듭니다.
2. 압축된 이미지를 Base64 문자열(`data:image/jpeg;base64,...`)로 변환합니다.
3. "반영하기" 버튼을 누르면 이 문자열이 유튜브 링크와 함께
   `/api/config` 로 전송되고, Cloudflare KV에 통째로 저장됩니다.
4. 메인 화면(`index.html`)은 접속할 때마다 `/api/config`를 호출해
   이 Base64 문자열을 그대로 `<img>` 태그의 `src`로 사용합니다.
   (별도 이미지 서버·CDN 경유 없이 바로 표시)

**안전장치**
- 서버(Function)에서도 이미지 용량을 재검사하여 5MB(base64 기준)를
  초과하면 저장을 거부합니다 → KV 무료 한도 초과나 페이지 로딩 지연 방지.
- 저장은 항상 "비밀번호 + 데이터 형식 검증"을 통과해야만 실행됩니다.
- 업로드 실수(사진이 아닌 파일 선택 등)는 저장 전 브라우저 단계에서 걸러집니다.

**향후 트래픽이 크게 늘어난다면 (참고용, 지금 당장은 불필요)**
성도 100명 규모, 주 1회 갱신 수준에서는 위 방식으로 충분하지만, 만약
방문자가 매우 많아지거나 사진/영상 자료가 늘어난다면 Cloudflare **R2**
(오브젝트 스토리지, 무료 티어 10GB)로 이미지 파일 자체를 옮기고 KV에는
파일 URL만 저장하는 구조로 확장할 수 있습니다. 지금 구조에서 관리자
화면의 사용 흐름은 동일하게 유지하면서 내부 저장 로직만 교체하면 되므로,
당장은 손대지 않아도 됩니다.

## 5. 새로 추가된 메뉴(인사말 · 교회 역사 · 섬기는 사람들) 및 포털형 상단 구성

**상단 유틸바 / 로고 / 내비게이션 / 히어로 슬라이더 / 컬러 타일 3개 / 바로가기 카드 5개 / 교회소식 위젯**은
모두 `index.html` 상단부에 정적 텍스트로 들어 있습니다. 아래 위치를 찾아 문구만 바꾸면 됩니다.

- 히어로 슬라이더 문구: `<div class="hero-slide s1">` 등 3개 블록의 `.verse`, `.cite` 텍스트
  (성경 구절을 원하는 대로 교체 가능, 슬라이드를 늘리려면 `.hero-slide.s4{ background:... }` CSS를
  추가하고 같은 구조의 블록을 하나 더 넣으면 자동으로 슬라이더에 포함됩니다)
- 교회소식 목록: `<ul class="notice-list">` 안의 `<li>` 한 줄씩 추가/삭제 (날짜와 제목)
- 인사말/역사/섬기는 사람들 상세 내용: `id="greeting"`, `id="history"`, `id="staff"` 섹션
  (사진을 넣고 싶다면 `.greeting-photo`, `.staff-avatar` 부분을 `<img src="사진경로.jpg">`로 교체)

이 내용들은 자주 바뀌지 않는 정보라 관리자 화면(admin.html)이 아니라 코드에 직접 넣어뒀습니다.
자주 바뀌는 **설교 영상·주보**만 관리자 화면에서 실시간으로 바꿀 수 있습니다.

> 참고: 컬러 타일과 바로가기 카드에 쓰인 이미지는 실제 사진이 아니라 CSS 그라디언트입니다.
> 저작권이 있는 스톡사진을 그대로 쓸 수 없어서, 같은 레이아웃을 색상으로 대체했습니다.
> 교회 실제 사진(성도들, 예배당 전경 등)이 있으면 `.shortcut-card`, `.hero-slide`의
> `background` 속성을 `background-image: url('사진경로.jpg')`로 바꿔서 실제 사진으로
> 교체할 수 있습니다.
